# 对局房间 UI 重做 —— 执行计划

参考旧版 `frontend/src/views/WerewolfGameView.vue` 的房间：三栏单屏、中间席位圆桌 + 中心状态、右栏日志（基本/详细两档）。
本轮只搬信息架构与视觉语法，不搬狼人杀专属面板（夜晚行动、狼人频道、遗言、投票面板）—— 那些等游戏模块真落地再说。

## Goal

房间页从「描述表 + 两个 tab 的表格」变成一张**看得懂正在发生什么**的桌子：
席位、谁在等、谁说了什么、模型在做什么，一屏之内看得见；完整记录仍在，但按日志读，而不是按数据库行读。

## Approach

1. 平台保持中文用户语汇，游戏保持中立：日志条目的类型不用游戏事件名判断，而是用**动作目录的 `audience`** + 平台事件词表分类
   （`room` → 发言、`seat` → 私密行动、`aiCall`/`aiFailed` → 模型、平台事件 → 系统、其余 → 阶段）。
2. 圆桌席位只显示平台知道的事：席位名、真人/AI、状态、是否正在被等待、该席位最近一条公开发言。
   票数、存活语义等属于游戏的东西不硬编码，公开变量原样列在左侧阶段卡。
3. 席位 >12 时退化网格：圆桌适合 3–12 席，文档允许 24 席，不能为了好看把上限写进界面。
4. 记录完整性与可读性分开：基本档看内容，详细档展开模型思考、工具调用、token 用量与原始 JSON。不新增数据来源，仍是同一份 `record`。

## 完成情况

- 房间改成三栏单屏：顶栏（对局 id、状态、我的席位/观战中、刷新）｜左（阶段卡、我的席位与规则、只给你看的信息、我的动作）｜中（席位圆桌 + 中心状态）｜右（记录日志）。
  「房间 / 记录」两个 tab 取消，记录就是右栏的日志。
- 房间是工作区不是文档：路由带 `fullBleed`，这一页不吃 `--container-max`（1120 → 满宽），圆桌才有 510px 的直径。
- 席位节点带最近一条公开发言的气泡（限制 3 行，`title` 给全文）。原本照旧版做侧挂气泡，实测在 360px 的圆桌里会挤成 31px 宽的竖条，改成节点下方、宽度即席位宽。
- 平台自己的 id 认识自己：状态变量里凡是等于本局席位 id 的值（含数组元素与对象键）都按席位名显示，
  `alive: [uuid, uuid]` 读作 `s1、s3`，`tally: {uuid: 2}` 读作 `s2: 2`。这是命名规则，不是游戏知识。
- 动作参数里 `kind: "seat"` 的字段在日志里也按席位名显示（`target: s2`）。

## 验证

- 门禁：`typecheck`、160 例单测（新增 `match-log` 分类用例）、`build`、`test:db`、`test:e2e` 9 例，全绿。
- 实机：演示环境里跑了一局三个 AI 席位的对局（23 行、20,343 token），房间页读得出阶段、席位气泡、

## 词表（中文界面）

界面里出现的每个词，要么是平台的（状态、席位状态、生命周期），要么是游戏自己的。后一类由游戏声明：
`GameModule.title`（游戏名）、`steps`（阶段名）、`words`（变量名、角色、结局、它自己的事件名）、
动作的 `label`。平台按词表渲染，没声明的一律原样显示 —— 平台不替游戏编中文，也不把机器名塞给玩家。

界面里留下的 ASCII 只有三类：席位名（`s1`）、账号名、以及模型 id 这类标识符；
原始记录行（详细档）本来就是给人对照日志用的，保持原样。

顺带改掉的两处英文外泄：连接测试的错误码（`unauthorized` 等）改成中文原因；未知错误码不再显示后端英文原文，
改成「操作没有成功（错误码）」并保留请求编号。
